# Google Sheet 저장 API 및 공휴일 연결

저장 잠금 개선: 브라우저 저장 요청은 입력 시점의 데이터를 복사해 순서대로 전송합니다. 팝업 저장 시 대기 중인 자동 저장 타이머를 취소해 중복 전송을 줄입니다. 서버는 JSON 변환을 완료한 뒤 잠금을 최대 30초 기다리며, 실패하면 데이터를 쓰지 않고 재시도 안내를 반환합니다. 반영하려면 `Code.gs`를 Apps Script에 적용해 새 버전으로 배포하고 `app.js`와 `index.html`도 사이트에 배포합니다.

1. [한국천문연구원_특일 정보](https://www.data.go.kr/data/15012690/openapi.do)에서 활용신청 후 인증키를 발급받습니다.
2. 업무대장 Google Sheet에서 **확장 프로그램 → Apps Script**를 엽니다.
3. 이 폴더의 `Code.gs` 내용을 Apps Script의 `Code.gs`에 붙여 넣고 저장합니다.
4. **프로젝트 설정 → 스크립트 속성 → 스크립트 속성 추가**에서 이름을 `DATA_GO_KR_SERVICE_KEY`, 값을 발급받은 인증키로 설정합니다. 일반 인증키(Decoding)를 권장하며 Encoding 키도 지원합니다. 키를 `config.js`나 Git 저장소에 넣지 않습니다.
5. **배포 → 배포 관리 → 수정 → 새 버전 → 배포**로 기존 웹 앱을 갱신합니다. 처음에는 **새 배포 → 웹 앱**을 선택하고 실행 계정을 본인으로, 액세스 사용자를 사이트 이용 범위에 맞게 설정합니다. 외부 요청 권한이 표시되면 승인합니다.
6. 기존 배포를 수정하면 URL은 유지됩니다. 새 URL이 발급되면 프로젝트 루트 `config.js`의 `apiUrl`에 `/exec` URL을 입력합니다.
7. 변경한 프런트엔드 파일을 GitHub Pages에 배포합니다.

## 업무대장 탭 (표 형태 백업)

`웹앱_업무대장` 탭에 웹 화면의 업무 표와 같은 형태로 2026년 9월 1일부터의 데이터를 기록합니다. JSON 데이터가 손상되거나 웹 화면을 쓸 수 없을 때 시트에서 바로 읽고 복구하기 위한 탭입니다.

- 1~2행: 월 / 일(요일) 머리글. A1에 최종 저장 시각이 표시됩니다.
- 열: 등록일, RMS·Jira, 업무명, 반영일, 진행현황, 비고, 9월 1일부터 (오늘과 마지막 입력일 중 늦은 날이 속한 달) 말일까지의 평일별 시간, 월마다 `N월 합계(일)`, 마지막에 `기간 합계(시간)`, `기간 합계(일)`. 일 = 시간 ÷ 8.
- 날짜는 화면처럼 주말·공휴일·추가 휴일·5월 1일을 뺍니다. 그날에도 시간이나 휴가가 입력되어 있으면 데이터가 빠지지 않도록 열을 넣습니다.
- 업무 행: 9월 이후 시간이 있거나, 등록일·반영일이 9월 이후이거나, 아직 완료·취소되지 않은 업무.
- 마지막 행: 날짜별 휴가(연차·반차·반반차, 대체휴가 여부).
- 열 너비: 등록일~비고 열은 그대로 두고, 그 뒤 시간·합계 열은 40으로 고정합니다.
- 정렬: 업무 행의 시간·합계 숫자(G3부터)는 우측 정렬, 머리글·업무 정보·휴가 행은 좌측 정렬입니다.

### 동기화 방식 (웹 → 시트 단방향)

- **저장할 때**: JSON을 저장한 뒤 이 탭을 다시 씁니다.
- **웹을 열 때(불러오기)**: 탭이 없거나, 마지막 저장 시각이 바뀌었거나, 새 달이 시작되어 표시 기간이 달라졌으면 다시 씁니다. 이미 최신이면 건너뜁니다(A1 메모에 동기화 기준값을 기록).
- 이 탭은 통째로 덮어쓰므로 시트에서 직접 수정한 내용은 웹에 반영되지 않고 다음 동기화 때 사라집니다. 수정은 웹에서 합니다.
- 탭 기록이 실패해도 JSON 저장·불러오기는 그대로 되며, 웹 화면에 실패 이유를 표시합니다.

적용 방법: `Code.gs`를 붙여 넣고 **새 버전으로 배포**합니다. 그다음 웹 페이지를 한 번 열면 자동으로 채워집니다. 바로 만들려면 Apps Script 편집기에서 `rebuildTableSheet`를 실행해도 됩니다.

## 월간 자동 백업 설정

1. Apps Script 편집기 상단의 실행할 함수 목록에서 `setupMonthlyBackupTrigger`를 선택합니다.
2. **실행**을 한 번 누르고 Google 권한을 승인합니다.
3. `웹앱_백업데이터` 탭과 `backupMonthlyData` 시간 기반 트리거가 생성되었는지 확인합니다.

트리거는 한국 시간 기준 매월 1일 01시대에 실행됩니다. `웹앱_업무데이터`의 JSON 전체와 원본 최종 저장 시각을 `웹앱_백업데이터`에 월별 1행으로 저장합니다. 같은 달에 함수를 다시 실행하면 중복 행을 만들지 않고 해당 월 백업을 갱신합니다. 즉시 동작을 확인하려면 `backupMonthlyData`를 직접 한 번 실행하면 됩니다.

Google Sheet에 기록되는 최종 저장 시각과 백업 시각은 한국 시간 기준 `YYYY-MM-DDTHH:mm:ss+09:00` 형식으로 저장됩니다.

Apps Script가 `getRestDeInfo`를 연도별로 조회하며 `isHoliday=Y`인 날짜만 반환합니다. 결과는 6시간 캐시하므로 공휴일 변경이 반영되기까지 최대 6시간 걸릴 수 있습니다. 대체공휴일과 임시공휴일은 API 제공 데이터를 따릅니다. 기존 업무대장 정책에 따라 5월 1일과 사용자가 등록한 추가 휴일도 계속 제외합니다.

공휴일 조회가 실패해도 업무는 불러옵니다. 화면에 실패 이유를 표시하고 기존 규칙 기반 임시 계산값을 사용합니다. 임시 계산값에는 새로 지정된 휴일이 누락될 수 있습니다. 인증키/활용신청 상태를 수정한 뒤 페이지를 새로고침하면 다시 조회합니다.

확인: 페이지 로딩과 연도 이동 시 공휴일이 작업일에서 제외되는지, 인증키가 없을 때 업무는 유지되고 오류 안내가 나오는지 확인합니다.
